# 食期管家 V2 产品需求文档

状态：设计基线
日期：2026-07-29
平台：Android 本地 APK

## 1. 产品定义

食期管家是一款面向家庭的保质期与库存管理工具。它帮助用户记录食品、药品、个护用品和家庭耗材的批次、数量、生产日期、有效期、保存状态与提醒，并通过相机减少录入负担。

V2 不再把产品限制为“食品 OCR”。同一个条码可以关联多个商品档案，同一个商品可以有多个批次；批次拥有独立日期、数量、状态和唯一编号。

当前阶段坚持：

- 本地优先，不依赖账号、云存储或联网服务。
- `expiryDate` 是排序和提醒的唯一最终日期。
- OCR 只生成待确认草稿，绝不绕过用户确认直接入库。
- 升级安装、数据迁移、导入和恢复不得破坏已有数据。
- 不提供医疗、营养或食品安全结论。

## 2. 重新设计的原因

现有版本把大量诊断状态、候选和操作同时堆在页面上，主要流程不够清楚。识别模块还混淆了四个不同阶段：

1. 看见了可能的文字区域。
2. OCR 得到了文字。
3. 文字被解析成商品字段。
4. 字段通过规则后被填入草稿。

2026-07-29 的失败视频证明，页面出现识别框并不代表字段会被填入。系统实际上读到了“复方硫酸软骨素滴眼液”和条码 `6917246211883`，但旧的食品语义过滤丢弃了药品名称，日期区域又没有获得足够的识别预算。

V2 必须让界面状态与真实处理阶段一致，并以“得到可用字段”而不是“出现文字框”作为成功标准。

## 3. 目标用户

### 3.1 主要用户

- 需要管理家庭食品、药品、个护用品和耗材的人。
- 经常补货，同一商品存在多个生产批次的人。
- 希望完全离线保存数据，不使用账号或云服务的人。
- 中老年用户，要求文字清楚、按钮好点、流程短、状态明确。

### 3.2 核心任务

1. 30 秒内扫描并确认一个新批次。
2. 打开首页即可知道什么快到期、今天应该处理什么。
3. 在库存列表直接完成“减少 1”“用完”“补货”。
4. 扫条码查找已有商品，或复用档案新增不同批次。
5. 在换手机前完成可验证的本地备份、分享和恢复。

## 4. 产品原则

### 4.1 结果优先

扫描页只展示用户能行动的信息：是否对焦、是否看见有效文字、已经得到哪些字段、下一步应该怎么做。帧数、队列长度和模型耗时只出现在诊断版。

### 4.2 批次优先

商品档案保存稳定信息，例如名称、类别、常用保质期和条码。批次保存本次购买的日期、数量、保存状态、开封状态和提醒。补货永远创建或更新批次，而不是覆盖旧批次。

### 4.3 一次计算提醒

智能提醒在新增批次时计算一次。只有生产日期、有效期、类别、保存方式、开封状态或用户模式改变时才重算，不根据每天减少的剩余天数漂移。

### 4.4 渐进确认

识别结果按字段展示证据和可信度。系统可以推荐，但必须允许用户查看关键帧、切换证据或改正字段后再保存。

### 4.5 可恢复

任何 schema 升级先备份、后迁移、再校验。JSON 导入以批次 UUID 幂等更新；Excel 导入先预览和校验，失败时整批回滚。

## 5. 信息架构

底部导航保留四个稳定目的地：

| 目的地 | 主要内容 | 首要操作 |
| --- | --- | --- |
| 总览 | 今日到期、临期、低库存、最近操作 | 扫描添加 |
| 库存 | 搜索、筛选、商品与批次列表 | 减少 1、补货 |
| 扫描 | 全屏相机、字段进度、关键帧 | 确认识别结果 |
| 设置 | 提醒、数据、识别与关于 | 导入或导出 |

“趋势”不是一级导航。统计只在总览的次级入口出现，避免挤占高频任务。

Android 紧凑屏幕使用四项导航符合官方建议的 3 至 5 个同等重要目的地；所有可点击区域至少为 48dp，正文小字号文本对比度至少 4.5:1。

## 6. 关键流程

### 6.1 扫描新增

1. 用户点击“扫描添加”。
2. 相机立即显示预览，并在 150ms 内显示对焦状态。
3. 快通道持续更新条码、文字区域和画面质量。
4. 慢通道只识别更清楚、能补齐字段的区域。
5. 得到“日期 + 商品名或条码”后进入可确认状态。
6. 用户查看 2 至 3 张关键帧和字段证据。
7. 用户确认后生成商品档案和独立批次。

扫描中不因“看见任意文字”提前停止。自动模式的默认完成条件是：

- 至少有一个可解释日期字段；并且
- 至少有商品名或条码之一。

日期特写模式只要求日期字段。用户始终可以带着部分结果进入确认页。

### 6.2 已知条码补货

1. 扫描命中本地条码关系后，先按 0、1、多个商品档案生成明确状态；只有本地 0 个结果时才查询联网商品库。
2. 本地 1 个结果时可以预选，但仍需用户点击“补货”；本地多个结果时不得隐式选择，主操作保持禁用直到用户明确选中档案。
3. 联网结果只能显式“填入新增表单”，不得自动保存，也不得覆盖已有本地档案。
4. 用户选择档案后进入“补货识别”。
5. 复用名称、类别和常用保质期，但重新识别本批次日期。
   补货表单首屏直接显示“相机识别本批次日期”，结果只回填新批次。
6. 保存为新批次；如果导入数据携带相同批次 UUID，则更新该批次。

### 6.3 日常消耗

库存行直接显示 `-1` 和“补货”。点击 `-1` 立即减少当前批次数量，并提供短时撤销；数量归零后提示“设为用完”，不强制跳页。

### 6.4 数据迁移

- 快速同步：按导入时间、生产日期或最终日期筛选 JSON 导出，通过 Android 分享面板发送到 QQ、微信或文件应用。
- 批量维护：Excel 导出和预览式导入。
- 恢复：导入前生成本地快照；解析、校验或写入失败时完整回滚。

## 7. 页面需求

### 7.1 总览

- 顶部显示日期和设置入口，不使用大面积装饰。
- 第一屏包含“今天到期”“7 天内”“低库存”三个可点摘要。
- 只有一个主要按钮：“扫描添加”。
- 临期列表按 `expiryDate` 升序，展示名称、批次、数量和剩余时间。
- 最近操作支持撤销最后一次减量。

### 7.2 库存

- 搜索框常驻，支持名称、条码和批次号。
- 筛选使用紧凑筛选条：全部、临期、已过期、低库存、已开封。
- 同一商品可以折叠多个批次，默认突出最早到期批次。
- 列表只按 `productProfileId` 聚合；同一条码关联的不同商品档案必须保持独立。
- 商品行显示在库批次数、总剩余量和最近到期日；点击后进入隐藏底部导航的全屏详情。
- 详情中的每个批次独立显示日期、数量、保存状态、可区分编号及行内编辑/更多操作。
- 高频操作 `-1` 与“补货”直接可见；编辑、归档和删除进入更多菜单。

### 7.3 扫描

- 相机预览占据主要空间，不放进装饰卡片。
- 顶部仅保留返回、手电筒和帮助。
- 文字框分为“已定位”和“已形成字段”两种视觉状态。
- 底部显示条码、名称、日期三个字段进度，不显示内部诊断计数。
- 支持“自动”和“日期特写”两种模式。
- 紧凑屏幕只保留一个上下文主操作；已有部分结果时，该操作进入核对页而不是清空会话。
- 点按画面设置 AF/AE/AWB 测光点；双指缩放；设备支持时提供曝光补偿。
- 识别到更好的关键帧时给出轻提示，但不遮挡预览。

### 7.4 确认

- 顶部展示 2 至 3 张关键帧，框出字段证据。
- 每个字段显示推荐值、证据来源和冲突状态。
- 低可信字段使用“请核对”，不能伪装成已确认。
- 商品名只显示一个高置信推荐；其他文字留在“查看全部文字”。
- 已知条码优先显示“补货到已有商品”，同时允许新建其他档案。
- 进入核对页后暂停相机或视频候选更新；返回扫描页时保留字段和关键帧。
- 查看识别依据后必须返回当前核对页，不能重启相机或丢失未采用结果。
- 底部固定一个主操作：“加入库存”或“确认补货”。

### 7.5 设置

- 设置首页只展示分组入口和当前摘要；提醒、JSON、Excel、备份恢复、识别与关于均进入独立全屏业务页，系统返回回到设置首页。
- 子页有未保存改动时，系统返回必须提示继续填写或放弃，不能静默丢失输入。
- 提醒：固定提醒或智能提醒、系统通知权限、测试通知。
- 数据：JSON 快速导入导出、Excel 批量导入导出、备份与恢复。
- 识别：离线模型状态、诊断模式、保留关键帧开关。
- 关于：版本、数据说明、隐私和开源许可。

备份恢复页只展示格式、schema、长度和 SHA-256 均通过校验的候选。恢复前必须再次校验目标、先保存当前库存安全备份，再以单个事务恢复并读回验证；任一步失败都保持当前库存不变。

## 8. 数据约束

- 商品档案、条码关系和批次必须分别存储。
- 条码与商品档案是多对多关系，不能使用条码作为数据库主键。
- 每个批次使用不可变 UUID。
- `expiryDate` 可以来自生产日期加保质期，也可以直接来自有效期至。
- 生产日期不得晚于设备当天；晚于当天的单日期默认解释为有效期候选。
- 两个无标签日期中，较早日期优先解释为生产日期，较晚日期优先解释为有效期，但仍需通过范围和字段证据校验。
- 日期缺失时不得自动选择“永不过期”。只能明确标为“日期待补充”。
- OCR 原始文本、结构化草稿和最终保存值必须可区分。

## 9. 质量目标

### 9.1 易用性

- 主要任务不超过三层页面。
- 高频按钮保持可见，触控区域至少 48dp。
- 中老年走查中，用户无需理解 OCR、候选、帧或置信度等术语即可完成任务。
- 页面不能同时出现互相矛盾的“识别中”和“识别完成”状态。

### 9.2 识别

- 相机预览不因分析队列阻塞，目标设备稳定达到至少 24fps。
- 字段状态反馈在新帧到达后 500ms 内更新。
- 常规清晰包装目标 2 秒内出现首个可用字段，5 秒内进入可确认状态。
- 困难日期 12 秒内仍无结果时，明确提示用户切换日期特写、点按对焦或调整反光。
- 对“画面中人眼可清晰阅读”的测试字段，字段召回目标不低于 90%。
- 错误日期不得静默预选，错误自动填充率目标低于 1%。

这些数值是验收门槛，不是当前完成情况。

### 9.3 数据

- 覆盖升级安装后，原有商品、批次、条码和提醒数据 100% 保留。
- JSON 重复导入相同批次 UUID 不产生重复记录。
- Excel 任意一行失败时，覆盖导入不得留下部分写入。

## 10. 非目标

- 不开发云同步、账号、共享家庭或应用商店发布。
- 不依赖需要密钥的在线 OCR。
- 不根据商品信息给出医疗或食用安全结论。
- 不用大模型替代可测试的日期规则和批次数据模型。
- 不以 APK 体积小为第一目标，但最终安装包不得超过 1GB。

## 11. 调研依据

- [Android Navigation bar](https://developer.android.com/develop/ui/compose/components/navigation-bar)：紧凑屏幕使用 3 至 5 个稳定目的地。
- [Android accessibility](https://developer.android.com/guide/topics/ui/accessibility/apps)：触控区域至少 48dp，小字号文本对比度至少 4.5:1。
- [Pantry Check inventory](https://pantrycheck.com/kb/inventory-screen/)：按类别和到期时间组织紧凑库存，并将数量、临期状态和扫码查找放在列表工作流中。
- [Smart Pantry](https://nowastefood.app/)：条码进入商品资料，再补充有效期；日常状态包括用完、丢弃、开封和过期。
- [PharmaVault](https://play.google.com/store/apps/details?id=com.meditrack.inventory)：药品场景需要批次、数量、有效期、条码与导入导出，而不只是食品名称。
